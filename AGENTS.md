# Working rules for AI roles

These rules apply to every AI that reads or changes this repository, whatever its role (PM, architect, planner, engineer, QA).

## Authority

1. `docs/PRD.md` is the master copy of the requirements. If anything in this repo conflicts with the PRD, the PRD wins.
2. The normative Magic sources (CR, MTR, IPG, current Oracle text, and the event's policy framework) win over everything in this repo about how the game and its policy work. Scenarios, concept files, summaries and earlier AI answers are **not** normative.
3. `docs/reference/chatgpt-2026-09-22/` is input only. Its `RULES.md` is a useful source of detail, but where it conflicts with the PRD or this file, the PRD and this file win.

## Changing requirements

- Never change a requirement silently. Every change to the PRD is a commit whose message references the affected IDs (for example, `PRD: revise FR-POL-2, add OQ-20`).
- IDs are stable. Never renumber or reuse one. Mark a withdrawn item as withdrawn; don't delete it.
- If the PRD doesn't say something, it's undecided. Add an open question (OQ-n); don't guess.
- Record every new decision in the decision log (PRD §10) together with its reasoning.

## Rulings and citations

- Every ruling, fix, penalty, or material rules conclusion cites its exact source: CR rule number, MTR or IPG section, Oracle text, or addendum section. A generic citation such as "the CR" is not enough.
- Record reasoning as **source → proposition → consequence**.
- Never invent a citation. If the basis can't be established, say so. `UNRESOLVED` is a valid result.
- A scenario stays **SOURCE CHECK REQUIRED** until the product owner validates it.
- Rules terms defined in the CR, MTR or IPG are never translated.

## Golden set

- Held-out evaluation cases must not be read while building or tuning the system.
- A scenario that is generated by AI only counts after the product owner signs it off.

## Git

- Work on a branch and open a pull request. Don't push directly to `main`.
- Keep commits small and describe *why* in the message.
